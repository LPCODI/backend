1. API 기본 규칙과 인증

1.1 기본 주소와 Content-Type

구분규칙
API Base{BASE_URL}/api/v1
JSON 요청Content-Type: application/json
이미지 업로드multipart/form-data. 브라우저가 boundary를 설정하도록 Content-Type을 직접 넣지 말고 FormData를 전달한다.
일시ISO 8601. 예: 2026-08-16T19:00:00+09:00
IDUUID 문자열. 프론트에서 숫자로 변환하지 않는다.

1.2 JWT 인증

/api/v1/auth/**만 인증 없이 호출할 수 있다. 나머지 API는 모두 아래 헤더가 필요하다.

Authorization: Bearer {accessToken}
401을 받으면 access token이 없거나 만료된 것이다. 저장한 refresh token으로 POST /auth/refresh를 호출한 뒤 원래 요청을 1회만 재시도한다. 마음대로 무한 재시도하지 않는다.

1.3 공통 성공 응답

데이터를 반환하는 API는 대부분 다음 envelope를 사용한다.

{
  "data": { ... },
  "meta": {
    "requestId": "req_..."
  }
}

DELETE, logout, 추천 피드백처럼 응답이 204 No Content 또는 body 없는 201인 API도 있다. 이때 JSON parsing을 시도하지 않는다.

1.4 공통 오류 응답

{
  "code": "VALIDATION_ERROR",
  "message": "요청값을 확인해 주세요.",
  "fieldErrors": [

  ],

2. 프론트 권장 연동 순서

1. 회원가입/로그인
2. 신체 프로필
3. 아바타 생성
4. 의류 2개 이상
5. TPO 분석
6. 날씨/추천
7. 착장 미리보기
8. 찜/피드백
  1. 로그인: access/refresh token을 받고 API client에 bearer token을 설정한다.
  2. 프로필: PUT /body-profile 후 POST /avatar/generate를 호출한다.
  3. 옷장: 서로 다른 카테고리의 의류를 2개 이상 업로드한다.
  4. 문장→TPO: POST /tpo/parse 결과를 사용자가 확인·수정하게 한다.
  5. 추천: 확정된 TPO 배열과 위치를 POST /recommendations에 보낸다.
  6. 착장: 빠른 결과는 /try-on/preview, AI 결과는 /try-on/render 후 GET polling을 사용한다.
선행 조건: 추천은 의류 2개 이상, 착장은 아바타가 필요하다. 화면에서 선행 조건을 먼저 검사하면 400 오류를 줄일 수 있다.

4. 인증 API

POST/api/v1/auth/signup인증 불필요

이유: 이메일/비밀번호 계정을 생성해 사용자별 옷장·추천 데이터의 소유자를 구분한다.

입력(JSON)제약반환
email*, password*, nickname*email 형식, password 8~72자, nickname 1~60자201 ApiResponse<UserResponse>
{ "email":"user@example.com", "password":"TestPass123!", "nickname":"코디핀" }

주요 오류: 409 EMAIL_ALREADY_EXISTS. 가입 후에도 token은 자동 발급되지 않으므로 login을 호출한다.

POST/api/v1/auth/login인증 불필요

이유: API 인증에 쓸 access token과 재발급에 쓸 refresh token을 발급한다.

입력(JSON)반환프론트 처리
email*, password*200 ApiResponse<TokenResponse>accessToken을 Authorization 헤더에, refreshToken을 보안 저장소에 보관
{
  "data": {
    "tokenType": "Bearer",
    "accessToken": "eyJ...",
    "accessExpiresIn": 3600,
    "refreshToken": "uuid.uuid",
    "refreshExpiresIn": 1209600
  },
  "meta": { "requestId": "req_..." }
}

주요 오류: 401 INVALID_CREDENTIALS.

POST/api/v1/auth/refresh인증 불필요

이유: access token 만료 시 로그인 유지. 사용한 refresh token은 폐기되고 새 refresh token이 발급된다.

입력(JSON)반환주의
refreshToken*200 ApiResponse<TokenResponse>응답의 access/refresh token 둘 다 기존 값을 교체

주요 오류: 401 INVALID_REFRESH_TOKEN. 이때는 로그아웃 처리한다.

POST/api/v1/auth/logout인증 불필요

이유: refresh token을 서버에서 폐기해 다시 사용할 수 없게 한다.

입력(JSON)반환프론트 처리
refreshToken*204 No Content성공 여부와 무관하게 로컬 토큰을 모두 삭제

5. 사용자·신체 프로필·아바타 API

5.1 사용자

GET/api/v1/users/meJWT

이유: 앱 시작/새로고침 시 현재 로그인 사용자를 복원한다. 입력 없음. 반환: 200 ApiResponse<UserResponse>.

PUT/api/v1/users/meJWT

이유: 닉네임, 퍼스널 컬러, 스타일 선호도를 추천용 프로필로 저장한다.

입력(JSON)제약반환
nickname*, personalColor, stylePreferencenickname 최대 60, personalColor 40, stylePreference 100자200 ApiResponse<UserResponse>
DELETE/api/v1/users/meJWT

이유: 회원 데이터와 Firebase Storage의 users/{userId}/ 객체를 정리한다. 반환: 204. 성공 후 token/캐시를 모두 삭제하고 로그인 화면으로 이동한다.

5.2 신체 프로필

GET/api/v1/body-profileJWT

이유: 아바타 생성 전에 저장된 신체 프로필을 불러온다. 입력 없음. 반환: 200 ApiResponse<BodyProfileResponse>. 없으면 404 BODY_PROFILE_NOT_FOUND.

PUT/api/v1/body-profileJWT

이유: 아바타 비율과 착장 설명에 사용할 신체 정보를 저장/갱신한다.

입력(JSON)제약/권장값반환
heightCm*, bodyType*, genderExpression*, consent*heightCm 100~230; consent는 반드시 true; bodyType 예: RECTANGLE, TRIANGLE, INVERTED_TRIANGLE; genderExpression 예: NEUTRAL200 ApiResponse<BodyProfileResponse>
{ "heightCm":170, "bodyType":"RECTANGLE", "genderExpression":"NEUTRAL", "consent":true }
DELETE/api/v1/body-profileJWT

이유: 신체 프로필과 연관 아바타를 제거한다. 반환: 204. 아바타를 참조하는 착장 결과도 DB cascade로 삭제될 수 있으므로 관련 프론트 캐시를 비운다.

5.3 아바타

POST/api/v1/avatar/generateJWT

이유: 신체 프로필로 기본 SVG 아바타를 생성해 착장의 바탕으로 사용한다. 입력 없음. 반환: 200 ApiResponse<AvatarResponse>. 프로필이 없으면 400 BODY_PROFILE_REQUIRED.

GET/api/v1/avatarJWT

이유: 현재 최신 아바타를 화면에 표시한다. 입력 없음. 반환: 200 ApiResponse<AvatarResponse>. 없으면 404 AVATAR_NOT_FOUND.

PUT/api/v1/avatarJWT

이유: 템플릿/옵션을 반영한 새 버전의 아바타를 생성한다.

입력(JSON)예시반환
templateId*, options(자유 key/value){"templateId":"STANDARD_FRONT","options":{"skinTone":"MEDIUM"}}200 ApiResponse<AvatarResponse>, version 1 증가
DELETE/api/v1/avatarJWT

이유: 아바타 DB 데이터와 저장 이미지를 삭제한다. 반환: 204. 성공 후 착장 관련 상태도 재조회한다.

6. 옷장 API

업로드 규칙: JPEG, PNG, WebP만 허용하며 최대 10MB다. 원본은 Firebase wardrobe, 현재 마스크 복사본은 masks 폴더에 저장된다.
GET/api/v1/wardrobeJWT

이유: 사용자 옷장 목록을 필터/페이징하여 조회한다.

Query기본/제약반환
category, season, color, page, sizepage=0, size=20; 서버가 size를 1~100으로 보정200 ApiResponse<WardrobeItemResponse[]>

총 개수/totalPages는 반환하지 않는다. 배열 길이가 size보다 작으면 마지막 페이지로 판단한다.

POST/api/v1/wardrobeJWT

이유: 의류 이미지와 속성을 저장해 추천/착장의 기본 데이터로 사용한다.

FormData key필수/권장값반환
image*(File), name*, category*, color, season, warmth, formality, fit, lengthcategory: TOP/BOTTOM/OUTER/SHOES/OTHER; warmth: 1~5; season: ALL/SPRING/SUMMER/FALL/WINTER; formality: CASUAL/SMART_CASUAL/FORMAL/SPORT201 ApiResponse<WardrobeItemResponse>

선택값을 비우면 color=미분류, season=ALL, warmth=3, formality=CASUAL, fit/length=REGULAR로 저장된다.

GET/api/v1/wardrobe/{itemId}JWT

이유: 의류 상세/수정 화면을 위해 한 건을 조회한다. 입력: path itemId*. 반환: 200 ApiResponse<WardrobeItemResponse>.

PUT/api/v1/wardrobe/{itemId}JWT

이유: 업로드 후 사용자가 분석 속성을 확인/수정한다.

입력(JSON)필수/제약반환
name*, category*, color, season, warmth, formality, fit, length, descriptionwarmth 1~5. PUT이므로 화면의 전체 필드를 보내는 것을 권장200 ApiResponse<WardrobeItemResponse>, analysisStatus=CONFIRMED
DELETE/api/v1/wardrobe/{itemId}JWT

이유: DB 의류 데이터와 Firebase의 원본/마스크 객체를 함께 제거한다. 반환: 204. 목록에서 즉시 제거한다.

POST/api/v1/wardrobe/{itemId}/reanalyzeJWT

이유: 의류 설명/분석 상태를 재생성하는 UI 흐름을 제공한다. 현재 서버는 기본 설명을 재생성하고 NEEDS_CONFIRMATION을 반환한다. 반환: 200 ApiResponse<WardrobeItemResponse>.

7. TPO·날씨 API

POST/api/v1/tpo/parseJWT

이유: “오전에 학교, 저녁에 데이트”와 같은 문장을 추천 API가 사용할 구조화된 일정으로 변환한다.

입력(JSON)형식반환
text*, baseDate, timezonebaseDate YYYY-MM-DD; timezone IANA 예: Asia/Seoul. 생략 시 오늘/서울200 ApiResponse<TpoParseResponse>
{ "text":"오전에 학교, 저녁에 데이트", "baseDate":"2026-08-20", "timezone":"Asia/Seoul" }

needsUserConfirmation은 현재 항상 true다. segments를 바로 추천에 넘기기 전 사용자가 시간/장소/활동/격식을 확인하게 한다.

GET/api/v1/weather/forecastJWT

이유: 위치/시간별 기온·강수·바람을 보여주고 추천 조합에 사용한다.

Query형식반환
latitude*, longitude*, atat=ISO 8601 offset datetime; 생략 시 현재 한국 시간200 ApiResponse<WeatherResponse>

fallback=true 또는 source="FALLBACK"이면 기상청 실시간값이 아닌 계절 기본값이다. UI에 “예상 날씨” 안내를 표시한다.

8. 코디 추천 API

POST/api/v1/recommendationsJWT

이유: TPO, 위치/날씨, 희망 분위기와 보유 의류를 종합해 1~3개 코디를 생성한다.

입력(JSON)제약반환
tpoSegments*(1개 이상), location*, desiredMood, maxOutfitslatitude -90~90, longitude -180~180, maxOutfits 1~3(기본 3)201 ApiResponse<RecommendationResponse>
{
  "tpoSegments": [{
    "startAt":"2026-08-20T19:00:00+09:00",
    "locationText":"해운대", "activity":"데이트", "formality":"SMART_CASUAL"
  }],
  "location": { "latitude":35.1587, "longitude":129.1604 },
  "desiredMood":"깔끔한 여름밤", "maxOutfits":3
}

선행 조건: 의류 2개 이상. 부족하면 400 INSUFFICIENT_WARDROBE. 응답의 outfits[].id가 찜/착장에 사용할 outfitId다.

GET/api/v1/recommendations/{id}JWT

이유: 추천 상세 화면/새로고침에서 저장된 결과를 복원한다. 입력: path id*. 반환: 200 ApiResponse<RecommendationResponse>. 없거나 내 것이 아니면 404 RECOMMENDATION_NOT_FOUND.

POST/api/v1/recommendations/{id}/regenerateJWT

이유: 기존 조건을 다시 입력하지 않고 새 추천 레코드를 생성한다. request body 없음. 반환: 201 ApiResponse<RecommendationResponse>. 반환된 새 id로 화면 상태를 교체한다.

9. 가상 착장 API

POST/api/v1/try-on/previewJWT

이유: AI 대기 없이 아바타와 의류 마스크를 합성한 SVG 미리보기를 즉시 생성한다.

입력(JSON)선행 조건반환
outfitId*내 추천 outfit + 아바타201 ApiResponse<TryOnResponse>, status=COMPLETED, renderType=PREVIEW, previewUrl 즉시 제공
POST/api/v1/try-on/renderJWT비동기

이유: 의류 원본을 OpenAI 이미지 편집에 전달해 고품질 착장을 시도한다. API key/호출이 없거나 실패하면 2D SVG로 자동 대체한다.

입력(JSON)즉시 반환최종 상태
outfitId*202 ApiResponse<TryOnResponse>, status=PROCESSING; previewUrl은 null이며 JSON에서 생략될 수 있음COMPLETED(AI), COMPLETED_FALLBACK(2D), FAILED
Polling: 응답의 id를 받은 후 1.5~2초 간격으로 GET /try-on/{id}를 호출한다. 60초 정도의 클라이언트 timeout을 두고 화면 이탈 시 polling을 취소한다.
GET/api/v1/try-on/{resultId}JWT

이유: 비동기 렌더 상태/결과 이미지를 조회한다. 반환: 200 ApiResponse<TryOnResponse>. previewUrl이 생기고 status가 PROCESSING이 아니면 polling을 종료한다.

DELETE/api/v1/try-on/{resultId}JWT

이유: 착장 결과 DB 행과 Firebase 결과 이미지를 삭제한다. 반환: 204.

10. 찜·피드백 API

GET/api/v1/favoritesJWT

이유: 사용자가 저장한 코디 스냅샷과 미리보기 URL을 목록으로 조회한다. 입력 없음. 반환: 200 ApiResponse<FavoriteResponse[]>.

12. TypeScript 연동 예시

12.1 공통 client

const API_BASE = import.meta.env.VITE_API_BASE_URL;

export async function apiFetch<T>(path: string, init: RequestInit = {}) {
  const accessToken = authStore.getState().accessToken;
  const response = await fetch(`${API_BASE}${path}`, {
    ...init,
    headers: {
      ...(init.body instanceof FormData ? {} : { "Content-Type": "application/json" }),
      ...(accessToken ? { Authorization: `Bearer ${accessToken}` } : {}),
      ...init.headers,
    },
  });

  if (response.status === 204) return undefined as T;
  const body = await response.json();
  if (!response.ok) throw body; // code, message, fieldErrors, requestId
  return body as T;
}

12.4 최소 공통 타입

export interface ApiResponse<T> {
  data: T;
  meta: { requestId: string };
}

export interface ApiError {
  code: string;
  message: string;
  fieldErrors: Array<{ field: string; message: string }>;
  requestId?: string;
}

export interface TpoSegment {
  startAt: string;
  locationText: string;
  activity: string;
  formality: "CASUAL" | "SMART_CASUAL" | "FORMAL" | "SPORT";
}

export interface TryOnResult {
  id: string;
  avatarId: string;
  outfitId: string;
  previewUrl?: string;
  renderType: "PREVIEW" | "AI" | "AI_FALLBACK";
  status: "PROCESSING" | "COMPLETED" | "COMPLETED_FALLBACK" | "FAILED";
  expiresAt: string;
}

13. 오류 처리·QA 체크리스트

13.1 프론트 오류 처리 우선순위

  1. HTTP status로 큰 흐름(401 토큰, 403 권한, 404 삭제됨, 409 중복)을 결정한다.
  2. code로 사용자 안내 문구/화면 분기를 결정한다.
  3. fieldErrors를 form input 아래에 표시한다.
  4. requestId를 클라이언트 로그/오류 제보에 함께 남긴다.
